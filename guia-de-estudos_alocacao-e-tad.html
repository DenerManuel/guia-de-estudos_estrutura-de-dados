TÓPICO 1

1. Fundamentos de Alocação de Memória

Conceito: o que é alocar memória? Alocar memória é reservar um espaço na gaveta do computador para guardar dados enquanto o programa está rodando. Essa "gaveta" é a memória RAM. Quando você cria uma variável em C, o computador separa um pedacinho dessa memória só para ela e coloca uma "etiqueta" com o nome da variável.
Analogia da gaveta Imagine um armário cheio de gavetas vazias. Quando você escreve int idade;, é como se você pegasse uma gaveta pequena, colasse a etiqueta "idade" e dissesse: "essa gaveta é minha, vou guardar um número inteiro aqui". Quando o programa termina, as gavetas são devolvidas.

Em C existem duas formas de conseguir essas gavetas: a alocação estática (tamanho fixo, decidido antes de rodar) e a alocação dinâmica (tamanho flexível, decidido enquanto o programa roda).

1.1 Alocação Estática (tamanho fixo)

Na alocação estática, o tamanho é escrito no próprio código, antes do programa rodar. Você já sabe quantos elementos vai precisar.

#include <stdio.h>

int main(void) {
    int v[10];          /* vetor de 10 inteiros: tamanho FIXO, decidido aqui */
    float nota;         /* uma variavel simples, tambem de tamanho fixo */
    char nome[50];      /* espaco para 49 letras + o caractere final '\0' */

    v[0] = 100;         /* posso usar normalmente */
    printf("%d\n", v[0]);

    return 0;
}
  • Quem decide o tamanho: o programador, na hora de escrever o código.
  • Quem gerencia a memória: o próprio computador (compilador). Você não precisa fazer nada.
  • Usa malloc() ou free()? Não. Nunca. Não é necessário.
  • Onde fica: normalmente na pilha (stack), uma área organizada e rápida.

Vantagens da alocação estática

  • É muito simples de escrever e de ler.
  • É rápida, porque o computador já reservou tudo antes de começar.
  • Não precisa de ponteiro nenhum.
  • Não precisa lembrar de liberar memória (nada de free).

Desvantagens da alocação estática

  • O tamanho não pode mudar durante a execução.
  • Se você colocar int v[1000]; e usar só 5 posições, desperdiça memória.
  • Se você colocar int v[10]; e o usuário quiser 50 números, falta espaço e o programa quebra.

1.2 Alocação Dinâmica (tamanho flexível)

Na alocação dinâmica, o tamanho é decidido enquanto o programa está rodando — normalmente porque depende do que o usuário digitou.

#include <stdio.h>
#include <stdlib.h>   /* obrigatorio para malloc, calloc, realloc e free */

int main(void) {
    int n;
    int *v;           /* ponteiro: vai guardar o ENDERECO da gaveta reservada */

    printf("Quantos numeros voce quer? ");
    scanf("%d", &n);  /* o tamanho so e conhecido AGORA, em tempo de execucao */

    /* Pede ao computador um bloco com espaco para n inteiros */
    v = (int *) malloc(n * sizeof(int));

    if (v == NULL) {          /* teste de seguranca obrigatorio */
        printf("Sem memoria!\n");
        return 1;
    }

    v[0] = 42;                /* usa como se fosse um vetor normal */
    printf("%d\n", v[0]);

    free(v);                  /* devolve a memoria para o computador */
    v = NULL;                 /* evita ponteiro solto */

    return 0;
}
  • Quem decide o tamanho: o programa, na hora da execução (com base na digitação do usuário).
  • Quem gerencia: o programador. Você pede com malloc/calloc e devolve com free.
  • Onde fica: numa área chamada monte (heap), que é maior e mais flexível que a pilha.

Vantagens da alocação dinâmica

  • O tamanho se adapta à necessidade real do programa.
  • Aproveita melhor a memória, sem desperdício.
  • Permite crescer ou diminuir depois, com realloc.

Desvantagens da alocação dinâmica

  • É mais complexa: exige ponteiros e atenção redobrada.
  • Se você esquecer o free, a memória fica presa até o programa fechar (vazamento).
  • Você precisa testar sempre se o ponteiro veio NULL.

1.3 Tabela comparativa simples: tamanho fixo vs tamanho flexível

Dica de estudo Se você já sabe o tamanho e ele nunca muda, use estática. Se o tamanho vem da digitação do usuário ou de um arquivo, use dinâmica. Essa frase resolve 90% das questões de prova.
TÓPICO 2

2. Operador sizeof e as Funções malloc() e calloc()

O que é o sizeof? sizeof é um operador que responde a pergunta: "quantos bytes esse tipo (ou essa variável) ocupa na memória?". Ele é importante porque o tamanho dos tipos muda de computador para computador. 
#include <stdio.h>

int main(void) {
    printf("int    = %zu bytes\n", sizeof(int));
    printf("float  = %zu bytes\n", sizeof(float));
    printf("double = %zu bytes\n", sizeof(double));
    printf("char   = %zu bytes\n", sizeof(char));

    int v[5];
    printf("vetor v = %zu bytes\n", sizeof(v));   /* 5 * sizeof(int) */

    return 0;
}
Por que usar %zu e não %d? O sizeof devolve um número do tipo size_t, que é um inteiro sem sinal. O jeito certo de imprimir é com %zu. Usar %d pode gerar aviso do compilador.

Tamanhos mais comuns (podem variar)

TipoTamanho típicoGuarda o quê
char1 byteUma letra ou um número pequeno
int4 bytesNúmero inteiro
float4 bytesNúmero com casas decimais
double8 bytesNúmero decimal mais preciso

2.1 A função malloc() — Memory Allocation

O nome vem do inglês Memory Allocation (alocação de memória). Ela reserva um bloco de memória do tamanho que você pedir e devolve o endereço desse bloco.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *p;

    /* Quero espaco para 5 inteiros.
       sizeof(int) diz quantos bytes tem 1 inteiro.
       5 * sizeof(int) diz quantos bytes tem o bloco todo. */
    p = (int *) malloc(5 * sizeof(int));

    if (p == NULL) {              /* SEMPRE teste! */
        printf("Falha ao alocar memoria.\n");
        return 1;
    }

    /* ATENCAO: o conteudo aqui dentro e LIXO de memoria.
       Sao valores desconhecidos, restos de outros programas. */
    p[0] = 7;                     /* agora sim, guardamos algo nosso */
    printf("%d\n", p[0]);

    free(p);
    p = NULL;
    return 0;
}
  • O que recebe: a quantidade de bytes que você quer.
  • O que devolve: o endereço inicial do bloco, ou NULL se não conseguiu.
  • O que tem dentro: lixo de memória — valores indeterminados, nunca confie neles.

2.2 A função calloc() — Contiguous Allocation

O nome vem de Contiguous Allocation (alocação contígua). Ela reserva espaço para N elementos e, de brinde, limpa tudo colocando ZERO em cada byte.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *p;

    /* calloc(quantidade, tamanho de cada um) */
    p = (int *) calloc(5, sizeof(int));

    if (p == NULL) {
        printf("Falha ao alocar memoria.\n");
        return 1;
    }

    /* Todos os valores ja estao ZERADOS */
    printf("%d %d %d %d %d\n", p[0], p[1], p[2], p[3], p[4]);

    free(p);
    p = NULL;
    return 0;
}

2.3 Diferença essencial entre malloc() e calloc()

Aspectomalloc()calloc()
Como se chamamalloc(tamanho_em_bytes)calloc(quantidade, tamanho_de_cada)
Quantos parâmetros12

Analogia do quarto de hotel malloc é como receber um quarto de hotel que ainda não foi arrumado: tem coisas do hóspede anterior lá dentro. calloc é receber o quarto limpo e arrumado: tudo no lugar, tudo zerado. Os dois quartos são do mesmo tamanho — a diferença é a arrumação inicial.

2.4 Teste Obrigatório de Segurança

A memória do computador é limitada. Se você pedir um bloco gigante, o sistema pode dizer "não tenho". Quando isso acontece, malloc e calloc devolvem NULL — que significa "ponteiro para lugar nenhum".

Pegadinha clássica de prova Usar a memória sem testar se o ponteiro é NULL. Se você fizer p[0] = 10; com p valendo NULL, o programa trava na hora (erro de segmentação). O teste abaixo é obrigatório: 
p = (int *) malloc(n * sizeof(int));

if (p == NULL) {          /* se veio NULL, NAO use a memoria */
    printf("Erro: memoria insuficiente.\n");
    return 1;             /* sai do programa com codigo de erro */
}

/* so daqui para baixo e seguro usar p */
p[0] = 10;
TÓPICO 3

3. Redimensionando e Liberando Memória

3.1 realloc() — mudar o tamanho de um bloco que já existe

realloc vem de reallocation (realocação). Serve para dizer: "eu tinha um bloco de 5 inteiros, agora quero um de 10".

Como usar com segurança Nunca escreva v = realloc(v, novo_tamanho);. Se o realloc falhar, ele devolve NULL e você perde o endereço antigo que estava em v — a memória antiga fica perdida para sempre. Use sempre um ponteiro temporário. 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *v;
    int *temp;   /* ponteiro TEMPORARIO: guarda o resultado antes de confirmar */

    v = (int *) malloc(5 * sizeof(int));
    if (v == NULL) return 1;

    v[0] = 1;
    v[1] = 2;

    /* Quero aumentar de 5 para 10 posicoes */
    temp = (int *) realloc(v, 10 * sizeof(int));

    if (temp == NULL) {
        /* Deu errado! O bloco antigo (v) continua valido.
           Nao perdi nada. Posso continuar usando v com 5 posicoes. */
        printf("Nao consegui aumentar. Mantendo as 5 posicoes.\n");
        free(v);
        v = NULL;
        return 1;
    }

    v = temp;    /* agora sim: v aponta para o bloco maior */

    v[9] = 999;
    printf("%d\n", v[9]);

    free(v);
    v = NULL;
    return 0;
}

O que o realloc faz por dentro (versão simples)

  1. Se der, ele estica o bloco no mesmo lugar — os dados antigos ficam onde estão.
  2. Se não der, ele procura outro lugar, copia os dados antigos para lá e libera o bloco velho automaticamente.
  3. Se não conseguir de jeito nenhum, devolve NULL e não mexe no bloco antigo.

3.2 free() — devolver a memória

free significa "liberar". É o comando que devolve o bloco para o computador, para que ele possa ser usado por outra parte do programa.

free(v);      /* devolve o bloco alocado com malloc/calloc/realloc */
v = NULL;     /* boa pratica: deixa o ponteiro apontando para lugar nenhum */
Por que fazer v = NULL depois do free? Porque o endereço antigo continua guardado dentro de v, mas aquele endereço não é mais seu. Se você usar v de novo por descuido, o programa pode fazer algo errado silenciosamente. Colocando NULL, qualquer uso indevido trava imediatamente e você descobre o erro rápido.

3.3 Cuidados e Pegadinhas de Prova

Memory Leak (Vazamento de Memória) Acontece quando você pede memória e esquece de devolver com free, ou quando perde o endereço guardado no ponteiro. O programa continua rodando, mas a memória vai ficando presa, presa, presa... até o computador ficar lento ou o programa ser encerrado.

Exemplo de vazamento por perda de endereço: 
int *p = (int *) malloc(10 * sizeof(int));
p = (int *) malloc(20 * sizeof(int));   /* ERRO! O primeiro bloco se perdeu */
free(p);                                 /* so libera o segundo bloco */
Dangling Pointer / Use After Free "Ponteiro pendurado" é um ponteiro que ainda guarda um endereço, mas aquele endereço já foi liberado. Ler ou escrever ali é comportamento indefinido: pode funcionar, pode mostrar lixo, pode travar tudo. 
int *p = (int *) malloc(sizeof(int));
*p = 5;
free(p);            /* memoria devolvida */
printf("%d", *p);   /* ERRO! Lendo depois do free (use after free) */
Double Free Acontece quando você chama free duas vezes no mesmo bloco. O computador pode tentar liberar algo que já não é seu e o programa aborta. 
int *p = (int *) malloc(sizeof(int));
free(p);
free(p);     /* ERRO! Ja liberei esse bloco uma vez */
p = NULL;    /* se tivesse feito isso antes, o segundo free seria inofensivo */
Detalhe importante: free(NULL) é permitido e não faz nada. Por isso colocar p = NULL depois do free protege contra double free acidental.
Regra de ouro Para cada malloc ou calloc que dá certo, deve existir exatamente um free. Nem zero, nem dois.
TÓPICO 4

4. Introdução a Tipo Abstrato de Dados (TAD)

Conceito simples TAD = Dados (uma struct) + Operações permitidas (funções que mexem nesses dados). Ou seja: você junta as informações com as ações que fazem sentido sobre elas, e esconde os detalhes internos de quem vai usar.
Analogia da calculadora Você usa uma calculadora apertando os botões: soma, subtrai, divide. Você não precisa saber como os circuitos eletrônicos por dentro funcionam. Os botões são a "interface" e os circuitos são a "implementação". Isso é um TAD: você sabe o que a calculadora faz, mas não precisa saber como ela faz.

4.1 Diferença entre Struct e TAD

AspectoStructTAD
O que juntaApenas variáveis (dados)Variáveis + funções que operam sobre elas
Tem comportamentos?Não, só guarda informaçãoSim, tem operações definidas
Quem mexe nos dados?Qualquer parte do código, diretoPreferencialmente só as funções do TAD
Exemplostruct { float x, y; } Ponto;Ponto + criarPonto() + distancia()
Resumindo em uma frase A struct só guarda. O TAD guarda e sabe fazer coisas.

4.2 Benefícios do TAD

  • Organização: cada coisa fica no seu lugar. O que é do aluno fica junto do aluno.
  • Reuso: você cria o TAD Aluno uma vez e usa em vários programas diferentes.
  • Manutenção fácil: se precisar mudar como a média é calculada, você mexe em um lugar só.
  • Separação entre quem usa e quem implementa: quem usa só precisa saber que calcularMedia(a) devolve a média; não precisa ver a conta por dentro.
  • Menos erro: ninguém sai mexendo nos dados de qualquer jeito; todos usam as funções certas.
TÓPICO 5

5. Estrutura de um TAD em Linguagem C

Na prática, um TAD em C é dividido em 3 arquivos, cada um com um papel bem claro.

5.1 O arquivo .h (Interface)

  • Declara a struct (os dados).
  • Declara os protótipos das funções (só o cabeçalho, sem o corpo).
  • Usa o Header Guard para o arquivo não ser incluído duas vezes por engano.
O que é Header Guard? São três linhas mágicas: #ifndef NOME_H, #define NOME_H e #endif. Elas significam: "se NOME_H ainda não foi definido, defina agora e leia o conteúdo; se já foi, ignore tudo". Assim o arquivo nunca é lido duas vezes na mesma compilação. 
/* ============ ponto.h ============ */
#ifndef PONTO_H        /* se PONTO_H ainda nao foi definido... */
#define PONTO_H        /* ...define agora e leia o que vem abaixo */

/* Aqui mostramos O QUE o TAD faz, nao COMO ele faz. */

typedef struct {
    float x;
    float y;
} Ponto;

/* Prototipos: so o cabecalho, terminando em ponto e virgula */
Ponto criarPonto(float x, float y);
float distancia(Ponto a, Ponto b);

#endif                 /* fim do ifndef */

5.2 O arquivo .c (Implementação)

  • Contém o código real de cada função.
  • Começa incluindo o próprio .h.
/* ============ ponto.c ============ */
#include "ponto.h"
#include <math.h>    /* para usar sqrt (raiz quadrada) */

Ponto criarPonto(float x, float y) {
    Ponto p;        /* crio uma variavel do tipo Ponto */
    p.x = x;        /* preencho o campo x */
    p.y = y;        /* preencho o campo y */
    return p;       /* devolvo o ponto pronto */
}

float distancia(Ponto a, Ponto b) {
    float dx = a.x - b.x;       /* diferenca das coordenadas x */
    float dy = a.y - b.y;       /* diferenca das coordenadas y */
    return sqrt(dx * dx + dy * dy);   /* formula da distancia */
}

5.3 O arquivo main.c (Uso / Cliente)

  • Chama as funções do TAD.
  • Não precisa saber como elas funcionam por dentro.
  • Inclui apenas o .h.
/* ============ main.c ============ */
#include <stdio.h>
#include "ponto.h"     /* so o .h, nunca o .c! */

int main(void) {
    Ponto p1 = criarPonto(0, 0);   /* uso a funcao, sem ver a conta */
    Ponto p2 = criarPonto(3, 4);

    printf("Distancia entre os pontos = %.2f\n", distancia(p1, p2));

    return 0;
}
Como compilar os 3 arquivos juntos gcc main.c ponto.c -o programa -lm
O -lm no final serve para ligar a biblioteca de matemática (por causa do sqrt). O .h não entra na lista porque ele é incluído automaticamente pelo #include.

5.4 Exemplo prático: TAD Aluno

Arquivo aluno.h (Interface)

/* ============ aluno.h ============ */
#ifndef ALUNO_H
#define ALUNO_H

#define TAM_NOME 50     /* tamanho maximo do nome */

typedef struct {
    char nome[TAM_NOME];   /* texto com o nome do aluno */
    float nota1;           /* primeira nota */
    float nota2;           /* segunda nota */
} Aluno;

Aluno criarAluno(const char *nome, float nota1, float nota2);
float calcularMedia(Aluno a);
int verificarAprovacao(Aluno a);   /* 1 = aprovado, 0 = reprovado */

#endif

Arquivo aluno.c (Implementação)

/* ============ aluno.c ============ */
#include "aluno.h"
#include <string.h>   /* para usar strcpy */

Aluno criarAluno(const char *nome, float nota1, float nota2) {
    Aluno a;                    /* crio a struct */
    strcpy(a.nome, nome);       /* COPIO o texto (nao posso usar = em strings) */
    a.nota1 = nota1;            /* guardo a primeira nota */
    a.nota2 = nota2;            /* guardo a segunda nota */
    return a;                   /* devolvo o aluno pronto */
}

float calcularMedia(Aluno a) {
    return (a.nota1 + a.nota2) / 2.0;   /* media simples das duas notas */
}

int verificarAprovacao(Aluno a) {
    if (calcularMedia(a) >= 6.0) {      /* media maior ou igual a 6? */
        return 1;                        /* sim: aprovado */
    } else {
        return 0;                        /* nao: reprovado */
    }
}

Arquivo main.c (Uso)

/* ============ main.c ============ */
#include <stdio.h>
#include "aluno.h"

int main(void) {
    Aluno a = criarAluno("Maria", 8.0, 6.0);   /* crio o aluno */

    printf("Aluno: %s\n", a.nome);
    printf("Media: %.2f\n", calcularMedia(a));

    if (verificarAprovacao(a)) {               /* se devolveu 1 */
        printf("Situacao: APROVADO\n");
    } else {
        printf("Situacao: REPROVADO\n");
    }

    return 0;
}
Por que essa divisão ajuda tanto? É como um restaurante. O .h é o cardápio (o que você pode pedir). O .c é a cozinha (onde o prato é feito, e você não entra lá). O main.c é o cliente (só pede pelo cardápio). Se o cozinheiro mudar a receita, o cliente nem percebe — desde que o prato continue igual.
TÓPICO 6

6. Dicas para Prova e Exercícios Resolvidos

6.1 Resumo das principais pegadinhas de prova

1. Esquecer o #include <stdlib.h> Sem esse include, o compilador não conhece malloc, calloc, realloc nem free. Ele pode até compilar com aviso, mas o comportamento fica imprevisível.
2. Esquecer o free() Toda memória alocada com malloc/calloc precisa ser devolvida com free. Esquecer gera vazamento de memória.
3. Tentar copiar string com = em vez de strcpy() Em C, a.nome = "Maria"; está errado. Vetor de char não aceita atribuição direta. O certo é strcpy(a.nome, "Maria"); — e não esqueça o #include <string.h>.
4. Não checar o retorno NULL Depois de malloc, calloc ou realloc, sempre teste if (p == NULL). É a pegadinha mais cobrada de todas.
5. Fazer v = realloc(v, ...) sem ponteiro temporário Se falhar, você perde o endereço antigo e cria um vazamento de memória.
6. Usar a memória depois do free (use after free) Depois de free(p), o bloco não é mais seu. Coloque p = NULL; logo em seguida.
Checklist antes de entregar a prova
  • Incluí <stdio.h> e <stdlib.h>?
  • Testei if (p == NULL) depois de cada alocação?
  • Usei sizeof junto com o malloc?
  • Dei free em tudo que aloquei?
  • Coloquei p = NULL; depois de cada free?
  • Usei strcpy para copiar textos?
  • Usei ponteiro temporário no realloc?

6.2 Exercício resolvido 1 — vetor dinâmico

Enunciado: Peça ao usuário quantos números ele quer digitar. Aloque um vetor dinamicamente, leia os valores, mostre a soma e libere a memória.

Passo 1 — Entender o problema

O tamanho só é conhecido depois da digitação. Então precisamos de alocação dinâmica com malloc.

Passo 2 — Escrever o código

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n;              /* quantos numeros */
    int *v;             /* ponteiro para o vetor dinamico */
    int i;
    int soma = 0;       /* acumulador da soma */

    printf("Quantos numeros? ");
    scanf("%d", &n);

    if (n <= 0) {       /* cuidado com tamanho invalido! */
        printf("Quantidade invalida.\n");
        return 1;
    }

    v = (int *) malloc(n * sizeof(int));   /* pede o espaco */

    if (v == NULL) {                        /* testa o retorno */
        printf("Erro de memoria.\n");
        return 1;
    }

    for (i = 0; i < n; i++) {              /* le os valores */
        printf("Valor %d: ", i + 1);
        scanf("%d", &v[i]);
    }

    for (i = 0; i < n; i++) {              /* soma os valores */
        soma = soma + v[i];
    }

    printf("Soma = %d\n", soma);

    free(v);        /* devolve a memoria */
    v = NULL;       /* evita ponteiro solto */

    return 0;
}

Passo 3 — Conferir

  • Se o usuário digitar 3 e os valores 10, 20, 30, a saída é Soma = 60.
  • Testei NULL? Sim.
  • Dei free? Sim.
  • Coloquei v = NULL? Sim.

6.3 Exercício resolvido 2 — TAD Aluno

Enunciado: Crie um TAD Aluno com nome, nota1 e nota2. Ele deve ter funções para criar o aluno, calcular a média e dizer se ele foi aprovado (média maior ou igual a 6).

Passo 1 — Identificar os dados

Dados: nome (texto), nota1 (decimal), nota2 (decimal).

Passo 2 — Identificar as operações

Operações: criar aluno, calcular média, verificar aprovação.

Passo 3 — Escrever o .h

#ifndef ALUNO_H
#define ALUNO_H

#define TAM_NOME 50

typedef struct {
    char nome[TAM_NOME];
    float nota1;
    float nota2;
} Aluno;

EXEMPLO 1

Vetor Dinâmico Básico

O exemplo mais clássico: o usuário diz quantos números quer, o programa reserva o espaço na hora e depois devolve.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n;              /* quantos numeros o usuario quer guardar */
    int *v;             /* ponteiro que vai apontar para o vetor */
    int i;

    printf("Quantos numeros voce quer guardar? ");
    scanf("%d", &n);

    /* Pede ao computador um espaco para 'n' inteiros */
    v = (int *) malloc(n * sizeof(int));

    /* Teste de seguranca: a memoria foi mesmo conseguida? */
    if (v == NULL) {
        printf("Erro: nao foi possivel alocar memoria!\n");
        return 1;
    }

    /* Lendo os valores digitados */
    for (i = 0; i < n; i++) {
        printf("Digite o valor %d: ", i + 1);
        scanf("%d", &v[i]);      /* v[i] e o mesmo que *(v + i) */
    }

    /* Mostrando os valores */
    printf("\nVoce digitou: ");
    for (i = 0; i < n; i++) {
        printf("%d ", v[i]);
    }
    printf("\n");

    /* Devolve a memoria para o computador */
    free(v);
    v = NULL;

    return 0;
}
O que aconteceu aqui? n é uma variável normal, guardada na pilha. v é um ponteiro que guarda o endereço de um bloco no heap. O bloco só existe porque pedimos com malloc — e só continua existindo até o free.
Detalhe importante v[i] e *(v + i) são exatamente a mesma coisa. Use v[i], que é mais fácil de ler.
EXEMPLO 2

Média de Notas com Alocação Dinâmica (usando calloc)

Aqui usamos calloc porque queremos que todas as notas comecem zeradas — assim não corremos o risco de somar lixo de memória.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n;                  /* quantidade de notas */
    int i;
    float *notas;           /* vetor dinamico de notas */
    float soma = 0.0;       /* acumulador da soma */

    printf("Quantas notas a turma tem? ");
    scanf("%d", &n);

    /* calloc = reserva N elementos E ja deixa todos zerados */
    notas = (float *) calloc(n, sizeof(float));

    if (notas == NULL) {        /* teste obrigatorio */
        printf("Erro: memoria insuficiente!\n");
        return 1;
    }

    for (i = 0; i < n; i++) {
        printf("Digite a nota %d: ", i + 1);
        scanf("%f", &notas[i]);
        soma = soma + notas[i];      /* ja vou somando */
    }

    /* Mostro a media da turma */
    printf("\nMedia da turma = %.2f\n", soma / n);

    free(notas);        /* devolvo a memoria */
    notas = NULL;       /* evito ponteiro solto */

    return 0;
}
Por que calloc aqui? É como preparar uma folha de prova em branco antes de começar. Se a folha já viesse com anotações antigas (lixo de memória), você poderia somar coisas que não deveria. Com calloc, a folha vem limpinha.

EXEMPLO 4

Uso Seguro de free() e realloc()

Este exemplo mostra o jeito certo de crescer um vetor e o jeito certo de liberar a memória no final.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *v;
    int *temp;      /* ponteiro TEMPORARIO para o realloc */
    int i;

    /* 1) Comeco com espaco para 2 inteiros */
    v = (int *) malloc(2 * sizeof(int));
    if (v == NULL) {
        printf("Erro ao alocar.\n");
        return 1;
    }

    v[0] = 1;
    v[1] = 2;

    /* 2) Quero aumentar de 2 para 4 posicoes.
          Uso um ponteiro TEMPORARIO para nao perder o v original. */
    temp = (int *) realloc(v, 4 * sizeof(int));

    if (temp == NULL) {
        /* Deu errado: o v original continua valido. Nao perco nada. */
        printf("Nao consegui aumentar. Vou ficar com 2 posicoes.\n");
        free(v);
        v = NULL;
        return 1;
    }

    v = temp;       /* agora sim: v aponta para o bloco maior */

    v[2] = 3;
    v[3] = 4;

    /* 3) Mostro os quatro valores */
    for (i = 0; i < 4; i++) {
        printf("%d ", v[i]);
    }
    printf("\n");

    /* 4) Libero a memoria e deixo o ponteiro seguro */
    free(v);
    v = NULL;

    return 0;
}
O erro que você NUNCA deve cometer 
/* JEITO ERRADO: */
v = (int *) realloc(v, 4 * sizeof(int));
if (v == NULL) { ... }   /* Se falhou, o endereco antigo ja se perdeu! */
Se o realloc falhar, ele devolve NULL e o bloco antigo continua existindo — mas você não tem mais o endereço dele. Isso é um vazamento de memória.
Resumo do exemplo
  • malloc para criar, realloc para crescer, free para devolver.
  • realloc sempre com ponteiro temporário.
  • free seguido de v = NULL.

Rastreando a Memória Passo a Passo

Vamos pegar um programa pequeno e acompanhar, linha por linha, o que acontece com a memória. Considere que neste computador sizeof(int) = 4 bytes.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *v = NULL;                            /* passo 1 */
    int i;

    v = (int *) malloc(3 * sizeof(int));      /* passo 2 */
    if (v == NULL) {                          /* passo 3 */
        printf("Erro de memoria!\n");
        return 1;
    }

    v[0] = 10;                                /* passo 4 */
    v[1] = 20;                                /* passo 5 */
    v[2] = 30;                                /* passo 6 */

    for (i = 0; i < 3; i++) {                 /* passo 7 */
        printf("%d ", v[i]);
    }
    printf("\n");

    free(v);                                  /* passo 8 */
    v = NULL;                                 /* passo 9 */

    return 0;
}

Tabela de rastreamento

Passo Comando Ponteiro v Bloco reservado Conteúdo do bloco
1 int *v = NULL; NULL (não aponta para nada) Nenhum —
2 malloc(3 * sizeof(int)) 0x1000 12 bytes (3 posições de 4 bytes) lixo de memória (valores desconhecidos)
3 if (v == NULL) 0x1000 Igual Teste passou: v não é NULL, seguimos em frente
4 v[0] = 10; 0x1000 Posição 0x1000 10
5 v[1] = 20; 0x1000 Posição 0x1004 10, 20
6 v[2] = 30; 0x1000 Posição 0x1008 10, 20, 30
7 printf("%d ", v[i]); 0x1000 Igual Saída na tela: 10 20 30
8 free(v); 0x1000 (endereço velho ainda guardado!) Devolvido ao computador A memória não é mais nossa. Usar v agora é erro grave.
9 v = NULL; NULL — Ponteiro zerado, seguro contra uso acidental
Repare no passo 8! Depois do free, o ponteiro v continua guardando o endereço 0x1000. Ele só não é mais um endereço válido. É exatamente por isso que existe o passo 9: colocar v = NULL para que qualquer uso indevido trave na hora e você descubra o erro.

Rastreando um realloc

Agora vamos acompanhar o que acontece quando aumentamos um bloco.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *v;
    int *temp;

    v = (int *) malloc(2 * sizeof(int));     /* passo 1 */
    if (v == NULL) return 1;

    v[0] = 5;                                /* passo 2 */
    v[1] = 6;                                /* passo 3 */

    temp = (int *) realloc(v, 4 * sizeof(int));   /* passo 4 */

    if (temp == NULL) {                      /* passo 5 */
        free(v);
        return 1;
    }

    v = temp;                                /* passo 6 */
    v[2] = 7;                                /* passo 7 */
    v[3] = 8;                                /* passo 8 */

    free(v);                                 /* passo 9 */
    v = NULL;                                /* passo 10 */

    return 0;
}
Passo Comando Ponteiro v Ponteiro temp Situação do bloco
1 malloc(2 * sizeof(int)) 0x2000 — Bloco de 8 bytes criado no endereço 0x2000, com lixo
2 v[0] = 5; 0x2000 — [5, lixo]
3 v[1] = 6; 0x2000 — [5, 6]
4 realloc(v, 4 * sizeof(int)) 0x2000 (ainda o antigo) 0x3000 (novo endereço) O computador achou outro lugar maior. Copiou [5, 6] para lá e liberou o bloco antigo automaticamente.
5 if (temp == NULL) 0x2000 0x3000 Teste passou: temp não é NULL, deu tudo certo
6 v = temp; 0x3000 0x3000 Agora v aponta para o bloco novo e maior
7 v[2] = 7; 0x3000 0x3000 [5, 6, 7, lixo]
8 v[3] = 8; 0x3000 0x3000 [5, 6, 7, 8]
9 free(v); 0x3000 0x3000 Bloco devolvido ao computador
10 v = NULL; NULL 0x3000 (mas esse bloco já não existe mais) Fim seguro do programa
Detalhe curioso O realloc pode devolver o mesmo endereço (se houver espaço sobrando ali do lado) ou um endereço diferente (se precisar mudar de lugar). Por isso nunca confie que o endereço vai continuar o mesmo.

Como o TAD Aluno fica na memória

Quando criamos Aluno a = criarAluno("Maria", 8.0, 6.0);, a struct ocupa um espaço contínuo na memória.

Resumo Relâmpago para a Véspera da Prova

Leia estes dez pontos antes de dormir. Eles cobrem praticamente tudo o que cai na prova.

1. Alocar memória = reservar espaço na RAM É pegar uma gaveta vazia do computador e colar uma etiqueta com o nome da variável, para guardar dados enquanto o programa roda.
2. Estática = tamanho fixo int v[10]; — o tamanho é escrito no código, o computador gerencia sozinho e não se usa malloc nem free.
3. Dinâmica = tamanho flexível O tamanho é decidido durante a execução. Usa ponteiro + malloc/calloc, e o programador é responsável por liberar com free.
4. sizeof conta os bytes sizeof(int) diz quantos bytes um inteiro ocupa. Como isso varia de máquina para máquina, use sempre sizeof junto com malloc. Imprima com %zu.
5. malloc não limpa; calloc zera malloc entrega a memória com lixo. calloc entrega tudo zerado. Essa é a diferença essencial entre as duas.
6. SEMPRE teste se o ponteiro é NULL Depois de malloc, calloc ou realloc, escreva if (p == NULL). Sem esse teste, o programa pode travar na hora.
7. realloc só com ponteiro temporário temp = realloc(v, novo); if (temp != NULL) v = temp;. Se você fizer direto em v e falhar, perde o endereço antigo e cria vazamento.
8. free devolve, e depois vira NULL Um free para cada alocação. Logo depois, p = NULL; para evitar ponteiro solto e double free.
9. Os três vilões da memória
  • Memory Leak: esquecer o free.
  • Dangling Pointer / Use After Free: usar depois do free.
  • Double Free: dar free duas vezes no mesmo bloco.
10. TAD = struct + funções Um TAD junta os dados (struct) com as operações que mexem neles (funções). Divide-se em .h (interface, com Header Guard), .c (implementação) e main.c (uso). E nunca esqueça: #include <stdlib.h> para memória e strcpy para copiar strings.
