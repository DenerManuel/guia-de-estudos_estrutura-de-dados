Guia de Estudos · ADS - Estruturas de Dados em C

Listas, Filas, Pilhas e Grafos — do zero, com analogias do dia a dia e código C simples

1. Introdução às Estruturas de Dados

Conceito Uma estrutura de dados é simplesmente uma forma de organizar e guardar dados para que depois seja fácil encontrar, usar e modificar esses dados. Nada mais do que isso.
Analogia do dia a dia Pense na sua cozinha. Você pode guardar os temperos de várias formas:
• Numa prateleira fixa com potes numerados → você acha qualquer pote na hora (vetor/array).
• Numa caixa onde cada pote está amarrado a outro por um barbante → você só acha o último seguindo o barbante desde o começo (lista encadeada).
• Numa pilha de pratos → você só tira o de cima (pilha).
• Numa fila do banco → o primeiro que chegou é o primeiro a ser atendido (fila).
Todas guardam as mesmas coisas. O que muda é como você insere, remove e acessa.
Toda estrutura tem 3 regras básicas 1. Inserir — como um novo dado entra.
2. Remover — como um dado sai.
3. Acessar — como eu chego até um dado específico.
Se você entende essas 3 regras para cada estrutura, você entendeu a estrutura inteira. Em prova, quase toda questão é sobre uma dessas três coisas.
Dica de estudo Sempre que estudar uma estrutura nova, faça uma tabela com 3 colunas: Inserir, Remover, Acessar. Preencha com o custo (rápido/lento) de cada operação. Isso resolve 90% das questões de múltipla escolha.

2. Listas

2.1 O que é uma lista?

Uma lista é uma coleção ordenada de itens. "Ordenada" aqui significa que existe uma posição para cada item: o primeiro, o segundo, o terceiro... A ordem importa e você pode falar "me dá o item da posição 3".

Analogia Uma lista é como a lista de chamada da professora: tem o aluno 1, o aluno 2, o aluno 3... Se você tira o aluno 2 da chamada, os outros precisam ser renumerados (isso é exatamente o que acontece no vetor quando você remove alguém do meio!).

2.2 Lista com Vetor (Array)

Conceito Os itens ficam guardados em gavetas de memória lado a lado, uma colada na outra. Cada gaveta tem um número (índice): 0, 1, 2, 3...
Analogia É como um armário de escaninho numerado: escaninho 0, 1, 2, 3... Se você sabe o número, vai direto na porta certa e pega o que quer. Não precisa abrir as outras.

✅ Vantagem: acesso direto e instantâneo

Quer o item da posição 2? Escreva lista[2] e pronto. Não importa se a lista tem 10 ou 10.000 itens — o tempo é o mesmo. Isso se chama acesso direto por índice.

❌ Desvantagem 1: tamanho fixo

O vetor nasce com um tamanho definido (int lista[10];). Se você precisar de 11 itens, problema. Se usar só 2, desperdiçou 8 espaços.

❌ Desvantagem 2: inserir/remover no meio exige "empurrar" todo mundo

Imagine o vetor [10, 20, 30, 40, 50] e queremos inserir 25 na posição 2 (entre o 20 e o 30):

  • Primeiro abrimos espaço: o 50 vai para a posição 5, o 40 para a 4, o 30 para a 3.
  • Depois colocamos o 25 na posição 2.
  • Resultado: [10, 20, 25, 30, 40, 50].

Ou seja: todos os elementos depois do ponto de inserção precisaram ser deslocados uma casa para a direita. Se o vetor tem 1 milhão de itens e você insere na posição 0, você move 1 milhão de itens. Isso é lento.

Para remover do meio é o contrário: você tira o item e desloca todo mundo para a esquerda para fechar o buraco. O vetor nunca pode ter buraco no meio.

Pegadinha de prova "Qual o custo de inserir um elemento no início de um vetor de N posições?"
A resposta é O(N) (ou "é preciso deslocar todos os elementos"), e NÃO "O(1)". Muita gente erra achando que inserir é sempre rápido. Inserir no fim (se ainda houver espaço) é O(1); inserir no início ou no meio é O(N).

2.3 Lista Simplesmente Encadeada

Conceito Em vez de gavetas coladas, temos nós (nódulos) espalhados pela memória, em lugares quaisquer. Cada nó guarda duas coisas:
• o dado (o valor);
• um ponteiro chamado proximo, que guarda o endereço de memória do próximo nó.
Existe uma variável especial chamada inicio (ou HEAD) que guarda o endereço do primeiro nó. O último nó tem proximo = NULL (nada), indicando o fim.
Analogia É uma caça ao tesouro. Você recebe a primeira pista (o HEAD). Cada pista diz onde está a próxima pista. Você não pode pular direto para a quinta pista — tem que seguir uma por uma, em ordem. A última pista diz "fim".

✅ Vantagens

  • Cresce dinamicamente: você cria um nó novo só quando precisa. Não existe tamanho fixo.
  • Inserir e remover não exigem deslocar ninguém: você só mexe em ponteiros (2 ou 3 linhas de código). Inserir no começo é instantâneo: O(1).

❌ Desvantagens

  • Acesso sequencial: para chegar no 5º elemento, você precisa começar no HEAD e andar nó por nó até lá. Não existe lista[4]. Acesso é O(N).
  • Gasta memória extra: cada nó carrega um ponteiro adicional.
  • Não dá para voltar: na lista simplesmente encadeada você só anda para frente.
Pegadinha de prova "Em uma lista encadeada, qual o tempo para acessar o último elemento?"
O(N), porque é preciso percorrer todos os nós desde o início. Já em um vetor, acessar o último elemento é O(1) (basta lista[N-1]). Essa troca de "inserção rápida × acesso rápido" é a essência da diferença entre as duas estruturas.

2.4 Lista Duplamente Encadeada

Conceito Igual à lista simplesmente encadeada, mas cada nó tem DOIS ponteiros:
• anterior — aponta para o nó de trás;
• proximo — aponta para o nó da frente.
Normalmente guardamos também um fim (ou TAIL), que é o endereço do último nó.
Analogia É como um ônibus com corredor de dois sentidos: você pode andar para a frente até o motorista ou para trás até a porta de saída. Na lista simplesmente encadeada, era um corredor de mão única — só ia para frente.

✅ Vantagens

  • Navegação nos dois sentidos: dá para percorrer do início para o fim ou do fim para o início.
  • Remoção mais fácil: se você já está no nó que quer remover, consegue achar o anterior rapidamente (sem precisar varrer a lista de novo).
  • Usando o fim, inserir no final também fica O(1).

⚖️ Trade-off (o preço a pagar)

  • Gasta mais memória: cada nó tem um ponteiro extra em relação à lista simples.
  • Código mais delicado: ao inserir ou remover, é preciso atualizar 4 ponteiros (dois do nó novo e dois dos vizinhos). Se esquecer um, a lista "quebra".
Dica de estudo Desenhe sempre no papel: caixinhas para os nós e setas para os ponteiros. Ao inserir um nó no meio de uma lista dupla, desenhe as setas antes de escrever o código. Quem desenha, não erra.

3. Fila (Queue)

Conceito A fila segue a regra FIFO — First In, First Out — ou seja, o primeiro que entra é o primeiro que sai.
Analogia A fila do banco ou a fila do supermercado. Quem chegou primeiro é atendido primeiro. Não existe "furar fila" na estrutura (e nem no banco, né?). Outro exemplo: a fila de impressão do computador — o primeiro documento enviado é o primeiro a ser impresso.

Operações principais

  • enfileirar (enqueue): insere um item no final da fila.
  • desenfileirar (dequeue): remove um item do começo (da frente) da fila.
  • frente / primeiro: só olha quem é o primeiro, sem remover.

Variáveis de controle

  • frente — índice de quem está na frente (o próximo a sair).
  • final — índice de onde o próximo item vai entrar.
  • (na fila circular) total — quantos itens existem agora.

3.1 Problema da Fila Linear

Imagine um vetor de 5 posições usado como fila:

[ ][ ][ ][ ][ ]
 0  1  2  3  4

Enfileiramos A, B, C:

[A][B][C][ ][ ]
 0  1  2  3  4    frente=0, final=3

Agora desenfileiramos A e B:

[ ][ ][C][ ][ ]
 0  1  2  3  4    frente=2, final=3

Perceba: as posições 0 e 1 estão vazias e desperdiçadas. Se agora tentarmos enfileirar D, E, F, G... o final chegará na posição 5 e a fila dirá "cheia!", mesmo tendo dois espaços livres lá atrás. Esse é o grande problema da fila linear.

3.2 Fila Circular (a solução)

Conceito A fila circular trata o vetor como se fosse um círculo: quando o final chega na última posição, ele volta para a posição 0. Assim, os espaços vazios da frente são reaproveitados.

O truque é o operador de resto da divisão (módulo) %:

final = (final + 1) % TAMANHO;

Se TAMANHO = 5:

  • final = 3 → (3+1) % 5 = 4
  • final = 4 → (4+1) % 5 = 0  ← deu a volta!
  • final = 0 → (0+1) % 5 = 1

O mesmo vale para a frente ao desenfileirar:

frente = (frente + 1) % TAMANHO;
Analogia É como uma mesa redonda de restaurante. Os garçons servem na cadeira 0, 1, 2, 3, 4 e depois voltam para a cadeira 0 — porque a mesa é redonda, não tem "fim". A fila circular faz isso com o vetor.
Pegadinha de prova Fila circular com TAMANHO = 5 e final = 4. Após um enfileirar, o novo valor de final é...
Resposta: 0. Porque (4 + 1) % 5 = 0. Muita gente responde 5 — mas a posição 5 não existe em um vetor de 0 a 4! Esse erro é clássico.
Dica de estudo Sempre confira como o "cheio" e o "vazio" são detectados na sua implementação. O jeito mais simples e à prova de erro é guardar um contador total: fila vazia é total == 0, fila cheia é total == TAMANHO.

4. Pilha (Stack)

Conceito A pilha segue a regra LIFO — Last In, First Out — ou seja, o último que entra é o primeiro que sai.
Analogias (tem várias!) • Pilha de pratos: você coloca um prato em cima e tira o de cima. Ninguém tira o prato do fundo sem tirar os de cima.
• Botão desfazer (Ctrl+Z): a última coisa que você fez é a primeira a ser desfeita.
• Botão voltar do navegador: volta para a última página que você visitou.
• Chamadas de função na recursão: o computador guarda na pilha "onde eu estava" antes de chamar a próxima função.

Operações principais

  • empilhar / push: coloca um item no topo.
  • desempilhar / pop: remove o item do topo e o devolve.
  • topo / peek: apenas olha qual é o item do topo, sem remover.
  • vazia / cheia: verificações de segurança antes de operar.

Variável de controle

topo — um número inteiro que indica o índice da última posição ocupada. Quando a pilha está vazia, usamos topo = -1.

Pegadinha de prova nº 1 topo() / peek() NÃO remove nada! Ele só devolve o valor do topo. Quem remove é pop() / desempilhar(). Essa é a pegadinha mais comum de todas em provas de pilha. Se a questão diz "a operação topo() remove o elemento do topo", ela é FALSA.
Pegadinha de prova nº 2 "Empilhar é sempre O(1)?" Sim, na pilha com vetor, desde que haja espaço — só mexemos no índice topo e não deslocamos ninguém. Diferente do vetor comum, onde inserir no meio é O(N).
Dica de estudo Grave as siglas: FIFO = Fila (First In, First Out) e LIFO = Pilha (Last In, First Out). Em prova, muitas vezes basta identificar se a situação é "fila de banco" (FIFO) ou "pilha de pratos" (LIFO).

5. Grafos

Conceito Um grafo é um conjunto de vértices (também chamados de nós) ligados por arestas (as linhas que conectam). Ou seja: pontos e ligações.
Analogias • Rede social: cada pessoa é um vértice; a amizade entre duas pessoas é uma aresta.
• Mapa de ruas: cada cruzamento é um vértice; cada rua é uma aresta.
• Rede de computadores: cada computador é um vértice; cada cabo é uma aresta.
• Rota de ônibus: cada parada é um vértice; cada trecho é uma aresta.

5.1 Tipos de grafo

  • Não direcionado (não dirigido): a ligação vale nos dois sentidos. Se A é amigo de B, B é amigo de A. A aresta é uma linha simples.
  • Direcionado (dígrafo): a ligação tem uma seta, ou seja, uma direção. Exemplo: no Instagram, você segue alguém, mas essa pessoa pode não te seguir. A aresta A → B não garante B → A.

5.2 Formas de representar um grafo no computador

a) Matriz de Adjacência

Conceito Uma grade (tabela) quadrada onde mat[i][j] = 1 significa "existe ligação do vértice i para o vértice j", e mat[i][j] = 0 significa "não existe ligação".

Exemplo com 3 vértices (0, 1, 2), onde 0 liga em 1 e 1 liga em 2:

012
0010
1001
2000
  • ✅ Vantagem: verificar se existe ligação entre i e j é instantâneo — basta olhar mat[i][j]. É O(1).
  • ❌ Desvantagem: gasta muita memória. Com 1.000 vértices, a matriz tem 1.000 × 1.000 = 1.000.000 de posições, mesmo que existam só 5 ligações. A maioria das posições fica com 0, "desperdiçado".

b) Lista de Adjacência

Conceito Para cada vértice, guardamos uma listinha apenas com os vizinhos dele. Se o vértice 0 só se liga ao 1, a lista do vértice 0 tem só um item.

O mesmo exemplo acima ficaria assim:

0 -> 1
1 -> 2
2 -> (vazia)
  • ✅ Vantagem: economiza muita memória quando o grafo tem poucas ligações (o que é comum no mundo real).
  • ✅ Também é mais rápido para percorrer "todos os vizinhos de um vértice", que é o que quase todo algoritmo de grafo faz.
  • ❌ Desvantagem: para saber se existe ligação entre i e j, é preciso percorrer a lista de i procurando j. Não é instantâneo como na matriz.
Pegadinha de prova "Quando usar matriz e quando usar lista de adjacência?"
• Grafo denso (muitas ligações, quase todos conectados com todos) → Matriz, porque a lista teria listas gigantes e a matriz não desperdiça tanto.
• Grafo esparso (poucas ligações em relação ao total possível) → Lista de adjacência, porque economiza memória.
Se a questão falar "grafo com poucas arestas", a resposta certa quase sempre é lista de adjacência.
Dica de estudo Antes de responder qualquer questão de grafo, desenhe os pontinhos e as linhas. Depois, desenhe a matriz e a lista ao lado. A resposta costuma aparecer na hora, sem esforço.

6. Pegadinhas de Prova — Resumo das Armadilhas

Armadilha 1 — Inserir no meio do vetor Inserir no início ou no meio de um vetor exige deslocar todos os elementos seguintes. É O(N). Só inserir no fim (com espaço livre) é O(1). Não confunda com a lista encadeada, onde inserir é rápido.
Armadilha 2 — peek() / topo() versus pop() / desempilhar() topo() e peek() apenas espiam o valor do topo — a pilha continua do mesmo tamanho.
pop() e desempilhar() removem o elemento — a pilha diminui em 1.
Se a questão disser que topo() remove, está errada.
Armadilha 3 — Fila circular e o % Em uma fila circular de tamanho TAM, depois de final = TAM - 1, o próximo final é 0, porque (TAM-1 + 1) % TAM = 0. Se a questão perguntar sobre a posição de índice TAM, a resposta é: essa posição não existe.
Armadilha 4 — Acesso sequencial versus acesso direto Vetor: acesso direto pelo índice v[4] → O(1).
Lista encadeada: para chegar ao 5º elemento é preciso percorrer nó por nó desde o HEAD → O(N). Nunca escreva lista[4] em lista encadeada!
Armadilha 5 — FIFO e LIFO trocados Fila = FIFO = primeiro que entra, primeiro que sai (fila de banco).
Pilha = LIFO = último que entra, primeiro que sai (pilha de pratos).
Trocar as duas siglas é o erro mais bobo e mais fatal.
Armadilha 6 — Esquecer de verificar vazia/cheia Toda função de empilhar, desempilhar, enfileirar e desenfileirar deve checar se a estrutura está cheia ou vazia antes de mexer nos índices. Em prova, questões que mostram código sem essa verificação estão testando se você percebe o risco de estouro de índice (acessar posição inválida).

Exemplo 1 — Inserir no meio: Vetor versus Lista Encadeada

Objetivo: inserir o valor 25 entre o 20 e o 30.

1.A — Usando VETOR (com deslocamento)

Situação inicial:

Índice:  0    1    2    3    4    5
Valor:  10   20   30   40   50    -

Passo 1: precisamos abrir espaço na posição 2. Vamos do fim para o começo, empurrando cada elemento uma casa para a direita.

PassoAçãoResultado do vetor
1Mover posição 4 (50) para a posição 510, 20, 30, 40, 50, 50
2Mover posição 3 (40) para a posição 410, 20, 30, 40, 40, 50
3Mover posição 2 (30) para a posição 310, 20, 30, 30, 40, 50
4Colocar 25 na posição 210, 20, 25, 30, 40, 50 ✅

Conclusão: 3 deslocamentos aconteceram. Se o vetor tivesse 1.000 elementos e a inserção fosse na posição 0, seriam 1.000 deslocamentos. Custo: O(N).

1.B — Usando LISTA SIMPLESMENTE ENCADEADA (só ponteiros)

Situação inicial (cada nó tem valor + ponteiro para o próximo):

HEAD -> [10|*] -> [20|*] -> [30|*] -> [40|*] -> [50|NULL]

Queremos inserir 25 entre o nó do 20 e o nó do 30. Digamos que já temos um ponteiro aux apontando para o nó do 20.

PassoAçãoEfeito
1Criar um nó novo com valor 25novo = [25|?]
2novo->proximo = aux->proximoO novo nó aponta para o nó do 30
3aux->proximo = novoO nó do 20 passa a apontar para o novo nó

Resultado final:

HEAD -> [10|*] -> [20|*] -> [25|*] -> [30|*] -> [40|*] -> [50|NULL]

Conclusão: nenhum elemento foi "empurrado". Mexemos em apenas 2 ponteiros. A inserção em si é O(1) — o único custo extra é o tempo de caminhar até a posição (que é O(N) se não tivermos o ponteiro do local).

Dica Repare na ordem das operações no passo 2 e 3: primeiro ligamos o nó novo ao próximo, e só depois ligamos o nó anterior ao nó novo. Se fizer ao contrário, você perde a referência do resto da lista. Isso cai em prova!

Exemplo 3 — Fila Circular: a volta com o %

Mesma fila, mas agora circular, com TAMANHO = 5. Continuando de uma situação onde final = 4:

#OperaçãoCálculo do índiceConteúdo do vetorfrentefinaltotal

5enfileirar(80)grava em 1; final = (1+1)%5 = 2[70, 80, , , 60]424

Interpretação: mesmo com final menor que frente (2 < 4), a fila está funcionando perfeitamente! Os elementos estão em ordem lógica: 60, 70, 80. Isso mostra que na fila circular não podemos comparar frente e final para saber se está cheia — é exatamente por isso que usamos o contador total.

Pegadinha "Se final == frente, a fila está vazia ou cheia?" Na implementação sem contador, ambos os casos dão final == frente — é ambíguo! Por isso se usa total (ou se deixa uma posição sempre vazia). Se a prova mostrar esse código sem contador, é uma armadilha.

É sempre esse equilíbrio: velocidade de consulta × economia de memória.

1. O nó da lista encadeada (a peça básica)

Todo nó tem um valor e um ponteiro para o próximo nó. É a estrutura mais importante de todas — pilha, fila e lista de adjacência podem ser construídas com ela.

#include <stdio.h>
#include <stdlib.h>

// Um no da lista: guarda um valor e o endereco do proximo no
typedef struct No {
    int valor;          // o dado guardado
    struct No *proximo; // ponteiro para o proximo no
} No;

No *inicio = NULL; // HEAD: comeca vazio (NULL = nada)

// Insere um valor no INICIO da lista (bem rapido: O(1))
void inserirInicio(int v) {
    No *novo = malloc(sizeof(No)); // 1. cria o no
    novo->valor = v;               // 2. guarda o valor
    novo->proximo = inicio;        // 3. aponta para o antigo primeiro
    inicio = novo;                 // 4. agora ele e o primeiro
}

// Percorre a lista do inicio ao fim e imprime
void imprimir(void) {
    No *aux = inicio;              // comeca pelo primeiro
    while (aux != NULL) {          // enquanto houver no
        printf("%d -> ", aux->valor);
        aux = aux->proximo;        // anda para o proximo
    }
    printf("NULL\n");
}

int main(void) {
    inserirInicio(30);
    inserirInicio(20);
    inserirInicio(10);
    imprimir();  // saida: 10 -> 20 -> 30 -> NULL
    return 0;
}

2. Lista duplamente encadeada (o nó com dois ponteiros)

#include <stdio.h>
#include <stdlib.h>

// O no agora tem DUAS setas: uma para tras e uma para frente
typedef struct No {
    int valor;           // o dado
    struct No *anterior; // aponta para o no de tras
    struct No *proximo;  // aponta para o no da frente
} No;

No *inicio = NULL; // primeiro no
No *fim = NULL;    // ultimo no

// Insere no INICIO da lista dupla
void inserirInicio(int v) {
    No *novo = malloc(sizeof(No));
    novo->valor = v;
    novo->anterior = NULL;  // e o primeiro, entao nao tem ninguem atras
    novo->proximo = inicio; // aponta para o antigo primeiro

    if (inicio != NULL) {   // se a lista NAO estava vazia
        inicio->anterior = novo; // o antigo primeiro olha para tras e ve o novo
    } else {
        fim = novo;         // lista estava vazia: o novo e tambem o ultimo
    }
    inicio = novo;          // o novo passa a ser o primeiro
}

// Imprime do inicio ate o fim
void imprimirFrente(void) {
    No *aux = inicio;
    while (aux != NULL) {
        printf("%d -> ", aux->valor);
        aux = aux->proximo;
    }
    printf("NULL\n");
}

// Imprime do fim ate o inicio (so e possivel na lista DUPLA!)
void imprimirTras(void) {
    No *aux = fim;
    while (aux != NULL) {
        printf("%d -> ", aux->valor);
        aux = aux->anterior;
    }
    printf("NULL\n");
}

int main(void) {
    inserirInicio(30);
    inserirInicio(20);
    inserirInicio(10);
    imprimirFrente(); // 10 -> 20 -> 30 -> NULL
    imprimirTras();   // 30 -> 20 -> 10 -> NULL
    return 0;
}
Dica Note que a lista dupla consegue andar para os dois lados — por isso a função imprimirTras existe. Na lista simples, isso seria impossível sem percorrer tudo de novo.

3. Pilha (Stack) — LIFO com vetor

#include <stdio.h>

#define TAM 5 // tamanho maximo da pilha

// A pilha tem os dados e um indice que marca o topo
typedef struct {
    int dados[TAM];
    int topo;      // indice do ultimo elemento colocado
} Pilha;

// Prepara a pilha para uso: topo = -1 significa VAZIA
void iniciar(Pilha *p) {
    p->topo = -1;
}

// Retorna 1 se a pilha estiver vazia, 0 caso contrario
int vazia(Pilha *p) {
    return p->topo == -1;
}

// Retorna 1 se a pilha estiver cheia, 0 caso contrario
int cheia(Pilha *p) {
    return p->topo == TAM - 1; // ultimo indice valido e TAM-1
}

// EMPILHAR: coloca um valor no topo
void empilhar(Pilha *p, int valor) {
    if (cheia(p)) {
        printf("Pilha cheia! Nao da para empilhar %d\n", valor);
        return;
    }
    p->topo++;                 // sobe o topo uma casa
    p->dados[p->topo] = valor; // guarda o valor ali
    printf("Empilhou %d\n", valor);
}

// DESEMPILHAR: tira o valor do topo e devolve ele
int desempilhar(Pilha *p) {
    if (vazia(p)) {
        printf("Pilha vazia! Nada para desempilhar\n");
        return -1; // -1 e um aviso de erro
    }
    int valor = p->dados[p->topo]; // pega o valor do topo
    p->topo--;                     // desce o topo uma casa
    return valor;
}

// TOPO (peek): SO OLHA o valor do topo, NAO remove nada
int topo(Pilha *p) {
    if (vazia(p)) {
        printf("Pilha vazia!\n");
        return -1;
    }
    return p->dados[p->topo]; // devolve sem mexer no indice
}

int main(void) {
    Pilha p;
    iniciar(&p);

    empilhar(&p, 7);
    empilhar(&p, 14);
    empilhar(&p, 21);

    printf("Topo (so olhando): %d\n", topo(&p));   // 21, pilha intacta

    printf("Desempilhou: %d\n", desempilhar(&p)); // 21
    printf("Desempilhou: %d\n", desempilhar(&p)); // 14

    printf("Topo agora: %d\n", topo(&p));          // 7

    return 0;
}
Lembre topo() devolve o valor mas não mexe em p->topo. Já desempilhar() faz p->topo--. Essa é a única diferença entre os dois no código — e é justamente o que cai na prova.

4. Fila Circular — FIFO com reaproveitamento de espaço

#include <stdio.h>

#define TAM 5 // tamanho maximo da fila

// A fila tem os dados, a frente, o final e um contador
typedef struct {
    int dados[TAM];
    int frente; // indice de quem vai SAIR
    int final;  // indice de onde o proximo VAI ENTRAR
    int total;  // quantos itens tem agora
} Fila;

// Prepara a fila: tudo zerado e vazia
void iniciar(Fila *f) {
    f->frente = 0;
    f->final = 0;
    f->total = 0;
}

// Retorna 1 se a fila estiver vazia
int vazia(Fila *f) {
    return f->total == 0;
}

// Retorna 1 se a fila estiver cheia
int cheia(Fila *f) {
    return f->total == TAM;
}

// ENFILEIRAR: entra sempre no FINAL
void enfileirar(Fila *f, int valor) {
    if (cheia(f)) {
        printf("Fila cheia! Nao da para enfileirar %d\n", valor);
        return;
    }
    f->dados[f->final] = valor;         // guarda no final
    f->final = (f->final + 1) % TAM;    // avanca e da a volta se precisar
    f->total++;                         // mais um item
    printf("Enfileirou %d\n", valor);
}

// DESENFILEIRAR: sai sempre da FRENTE
int desenfileirar(Fila *f) {
    if (vazia(f)) {
        printf("Fila vazia! Nada para desenfileirar\n");
        return -1;
    }
    int valor = f->dados[f->frente];     // pega quem esta na frente
    f->frente = (f->frente + 1) % TAM;  // avanca a frente e da a volta
    f->total--;                         // menos um item
    return valor;
}

// FRENTE (peek): so olha quem e o primeiro, sem remover
int primeiro(Fila *f) {
    if (vazia(f)) {
        printf("Fila vazia!\n");
        return -1;
    }
    return f->dados[f->frente]; // devolve sem mexer no indice
}

int main(void) {
    Fila f;
    iniciar(&f);

    enfileirar(&f, 10);
    enfileirar(&f, 20);
    enfileirar(&f, 30);
    enfileirar(&f, 40);
    enfileirar(&f, 50);

    printf("Primeiro da fila: %d\n", primeiro(&f)); // 10

    printf("Saiu: %d\n", desenfileirar(&f)); // 10
    printf("Saiu: %d\n", desenfileirar(&f)); // 20

    // Agora tem espaco! A fila circular reaproveita as posicoes 0 e 1
    enfileirar(&f, 60); // entra na posicao 0 (deu a volta!)
    enfileirar(&f, 70); // entra na posicao 1

    printf("Primeiro agora: %d\n", primeiro(&f)); // 30

    return 0;
}
Dica O segredo da fila circular está em duas linhas: final = (final + 1) % TAM; e frente = (frente + 1) % TAM;. Se você entender por que o % faz o índice "dar a volta", você entendeu a fila circular inteira.

5. Grafo — Matriz de Adjacência

#include <stdio.h>

#define V 5 // numero de vertices do grafo

// A matriz: mat[i][j] = 1 significa "i esta ligado a j"
int mat[V][V];

// Zera a matriz inteira (nenhuma ligacao)
void iniciar(void) {
    int i, j;
    for (i = 0; i < V; i++) {
        for (j = 0; j < V; j++) {
            mat[i][j] = 0;
        }
    }
}

// Cria uma ligacao entre a e b (grafo NAO direcionado)
void ligar(int a, int b) {
    mat[a][b] = 1; // a liga em b
    mat[b][a] = 1; // e b liga em a (dois sentidos)
}

// Mostra a matriz na tela
void mostrar(void) {
    int i, j;
    printf("   ");
    for (j = 0; j < V; j++) printf("%d ", j);
    printf("\n");
    for (i = 0; i < V; i++) {
        printf("%d: ", i);
        for (j = 0; j < V; j++) {
            printf("%d ", mat[i][j]);
        }
        printf("\n");
    }
}

// Verifica se existe ligacao (consulta instantanea!)
int existeLigacao(int a, int b) {
    return mat[a][b] == 1;
}

int main(void) {
    iniciar();
    ligar(0, 1);
    ligar(0, 2);
    ligar(1, 3);
    ligar(3, 4);

    mostrar();
    printf("0 liga em 1? %d\n", existeLigacao(0, 1)); // 1 (sim)
    printf("0 liga em 4? %d\n", existeLigacao(0, 4)); // 0 (nao)
    return 0;
}

6. Grafo — Lista de Adjacência (economiza memória)

#include <stdio.h>
#include <stdlib.h>

#define V 5 // numero de vertices

// Cada vizinho e um no de uma listinha encadeada
typedef struct Vizinho {
    int id;                  // o numero do vertice vizinho
    struct Vizinho *proximo; // proximo vizinho da lista
} Vizinho;

Vizinho *lista[V]; // um "cabecalho" de lista para cada vertice

// Zera todos os cabecalhos (nenhum vizinho)
void iniciar(void) {
    int i;
    for (i = 0; i < V; i++) {
        lista[i] = NULL;
    }
}

// Adiciona um vizinho na lista de um vertice (no inicio, bem rapido)
void adicionar(int a, int b) {
    Vizinho *novo = malloc(sizeof(Vizinho));
    novo->id = b;
    novo->proximo = lista[a]; // aponta para o antigo primeiro vizinho
    lista[a] = novo;          // passa a ser o primeiro da listinha
}

// Cria uma ligacao nos DOIS sentidos (grafo nao direcionado)
void ligar(int a, int b) {
    adicionar(a, b);
    adicionar(b, a);
}

// Mostra quem e vizinho de quem
void mostrar(void) {
    int i;
    for (i = 0; i < V; i++) {
        printf("%d -> ", i);
        Vizinho *aux = lista[i];
        while (aux != NULL) {
            printf("%d -> ", aux->id);
            aux = aux->proximo;
        }
        printf("NULL\n");
    }
}

// Verifica se existe ligacao (precisa percorrer a listinha)
int existeLigacao(int a, int b) {
    Vizinho *aux = lista[a];
    while (aux != NULL) {
        if (aux->id == b) return 1; // achou!
        aux = aux->proximo;
    }
    return 0; // percorreu tudo e nao achou
}

int main(void) {
    iniciar();
    ligar(0, 1);
    ligar(0, 2);
    ligar(1, 3);
    ligar(3, 4);

    mostrar();
    printf("0 liga em 1? %d\n", existeLigacao(0, 1)); // 1
    printf("0 liga em 4? %d\n", existeLigacao(0, 4)); // 0
    return 0;
}
Dica Perceba que a lista de adjacência é uma lista encadeada dentro de um vetor. Ou seja: se você entendeu a lista encadeada, você já sabe fazer lista de adjacência. As estruturas se conectam!

⚡ Resumo Rápido — Véspera de Prova

Os 10 pontos que resolvem a prova
  • 1. Estrutura de dados = forma de organizar dados. Toda estrutura define inserir, remover e acessar.
  • 2. Vetor: acesso direto por índice é O(1) (v[4]), mas inserir/remover no meio exige deslocar elementos → O(N). Tamanho é fixo.
  • 3. Lista simplesmente encadeada: nós espalhados + ponteiro proximo. Inserir/remover é rápido (só mexe em ponteiros), mas o acesso é sequencial a partir do HEAD → O(N).
  • 4. Lista duplamente encadeada: cada nó tem anterior e proximo. Anda nos dois sentidos, mas gasta mais memória e exige atualizar 4 ponteiros nas operações.
  • 5. Fila = FIFO (primeiro que entra, primeiro que sai). Entra no final, sai da frente. Variáveis: frente e final.
  • 6. Fila circular resolve o desperdício da fila linear usando (indice + 1) % TAM. Com final = 4 e TAM = 5, o próximo final é 0, nunca 5!
  • 7. Pilha = LIFO (último que entra, primeiro que sai). push empilha no topo, pop remove do topo, peek/topo só olha. Variável: topo (vazia = -1).
  • 8. peek()/topo() NÃO remove nada. Só pop()/desempilhar() remove. Essa é a pegadinha mais cobrada.
  • 9. Grafos = vértices + arestas. Matriz de adjacência: consulta O(1), mas gasta V² de memória. Lista de adjacência: economiza memória em grafos esparsos, mas consultar uma ligação é mais lento.
  • 10. Grafo direcionado tem setas (A→B não implica B→A). Não direcionado vale nos dois sentidos (a matriz fica simétrica).
